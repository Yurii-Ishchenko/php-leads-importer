# Проверка реального XLSX — 30 сентября 2026

Исходный файл работодателя использован только как локальные входные данные.
Он исключён из Git точной записью `/База даних.xlsx`, не включён в fixtures,
seeds или Docker build context. SQL dump исходных данных не создавался.
Этот отчёт содержит только агрегаты, контрольные суммы и технические результаты.

## Проверенный пользовательский flow

`GET /` → сессия и CSRF → `POST /imports` с multipart XLSX → Laravel →
сохранение upload в `storage/app/private/imports` → database queue → отдельный
worker → потоковый XLSX importer → пакетные транзакции в MySQL 8.4.11.

Использован настоящий HTTP-запрос через Nginx и PHP-FPM, а не прямой вызов
сервиса с локальным путём. Исходный workbook и сохранённый HTTP upload имеют
одинаковую SHA-256:

```text
82e3e9d3a5f98a459e474846131ac1abd2684e6b23234ddc39a7927fddb6346f
```

До первого запуска worker непосредственно в MySQL были проверены:
`imports.status=queued`, `processed_rows=0`, одно задание очереди `imports`,
ноль строк в `leads`. Финальная проверка выполнена свежей HTTP-загрузкой после
исправления найденных особенностей XLSX; ID финального импорта — 2.

## Найденные и исправленные проблемы

Первый диагностический запуск остановился по 120-секундному таймауту очереди
после 79 500 записанных строк. Причина — повторное чтение и разбор больших
страниц shared strings. Кэш заменён на небольшие страницы и ограниченный
кэш часто используемых значений. Повтор этого задания через Laravel
`queue:retry` завершился за 37,763 секунды без дополнительных дубликатов.

Полная сверка выявила, что телефоны в файле представлены формулами `=+…`.
Импорт исправлен: используются сохранённые результаты формул. В независимом
XML-аудите также учтены 608 числовых телефонных ячеек, в которых целое число
записано как `12345.0`: эта запись эквивалентна числовому значению `12345`.
Текстовые ячейки сохраняют свои символы без такой нормализации.

Финальная свежая HTTP-загрузка прошла с первой попытки, без ошибок и failed jobs.
Таким образом, при разработке был один таймаут; он устранён и не скрывается
итоговым нулевым количеством failed jobs. PHP `max_execution_time` не менялся:
PHP-FPM — стандартные 30 секунд, CLI worker — стандартный для CLI ноль.
Значение PHP-FPM сравнивалось с исходным PHP-образом. В application code и
конфигурации нет изменения лимита выполнения или `set_time_limit`.

## Независимость от исходного файла

После завершения финального импорта исходник был убран из корня проекта
с сохранением оригинала вне репозитория. При отсутствующем файле выполнен
перезапуск `app`, `web`, `queue`. Все сервисы запустились, MySQL остался healthy,
`GET /` вернул HTTP 200, показал рабочую форму загрузки и завершённый импорт.
До первой загрузки эта же страница работала на пустой базе.

После проверки оригинал возвращён в корень, чтобы сохранить предоставленные
пользователем данные. Он продолжает игнорироваться Git и может быть удалён
перед публикацией без влияния на запуск приложения.

Регрессионные тесты: 7 прошли, 44 assertions. Они создают собственные маленькие
XLSX и не зависят от реального файла. Laravel Pint и `composer validate --strict`
также прошли.
